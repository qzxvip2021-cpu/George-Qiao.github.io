01 / Overview

Project Overview

V4 is a flight-computer PCB design intended to bring inertial, barometric, GNSS, and removable-storage interfaces onto one board. The current source includes an RP2040, an LSM6DSK320XTR inertial sensor, a BMP390 barometer, a MAX-M10N-10B GNSS module, and a microSD interface.

My Role & Contributions

This is an independent engineering project developed with AI assistance. My contributions include AI-assisted work across schematic design, PCB layout and routing, firmware development, manufacturing-package review, and consistency checks, along with direct participation in design iterations and technical analysis. Firmware development is part of the project scope; completed firmware testing and operation on hardware are not verified.

Verified design artifact

The named components, six copper layers, and 50 × 160 mm board outline are present in the audited design source. Their presence establishes design intent, not demonstrated hardware operation.

02 / Requirements

Design Objectives & Constraints

The design brings flight-data interfaces, onboard logging, debug, and power distribution into a narrow six-layer board. Layout work must balance sensor placement, GNSS RF routing, reference planes, connector access, assembly data, and a fixed mechanical envelope.

Design goal

Integrated sensing

Provide electrical interfaces for motion, pressure, position, and storage subsystems.

Verified constraint

Board envelope

Maintain the audited 50 × 160 mm Edge.Cuts profile across six copper layers.

Pending review

Production behavior

Controlled impedance, stencil treatment, CAM output, and connector fit still require review.

04 / PCB

PCB Design & Engineering Decisions

The stack assigns signal, reference, and distribution roles rather than treating every internal layer as interchangeable. Two internal ground-reference layers sit alongside a low-speed digital layer and a power-distribution layer between the outer copper layers.

  2. L2GND ReferenceIn1.Cu
  3. L3Low-Speed DigitalIn2.Cu
  4. L4GND ReferenceIn3.Cu
  5. L5Power DistributionIn4.Cu
  6. L6B.CuComponents and routing

Interface identity follows function

The current four-pin expansion connector is documented as 3.3 V AUX GPIO on GP23/GP24, not a display or I²C subsystem. A legacy reference designator remains, which is why labels must be checked against current electrical intent.

RF and assembly constraints stay visible

The release notes retain GNSS impedance review, USB locator-area review, and user-specified flash paste treatment as production-file approval gates rather than silently treating them as resolved.

05 / Release preparation

Design Iterations & Manufacturing Preparation

The Rev A package records a frozen source state and groups Gerber, drill, assembly, and verification outputs. Independent read-only checks found the archive internally intact and found strong structural agreement between the current design source and those outputs.

Iteration evidence

Confirmed design change. Earlier source and documentation used Display-interface descriptions; the current active design defines the connector as 3.3 V AUX GPIO on GP23 and GP24, not I2C/display. The legacy J_DISPLAY1 reference remains.

Legacy source and documentation remnants. Historical material referenced a 50 × 180 mm board, while the current Edge.Cuts and fabrication profile centerline are 50 × 160 mm. Older In1.Cu and In3.Cu GND zone bounds remain in source.

Unresolved review findings. Manufacturing review detected procurement-field differences for J_RF1, J_SD1, J_USB1, and U2, plus retained GND zone definitions. Inspection found only that GND Gerber command centers remained inside the current profile; this does not establish all rendered copper or aperture extents or resolve CAM/electrical equivalence.

06 / Evidence

Verification Status & Known Limitations

Verification is separated by evidence type so that a file check is never presented as a hardware result. Stored reports were inspected; the design tools were not freshly rerun during the audit.

Independently checked

Source and package identity

Current PCB and schematic hashes matched the audited baseline; all 50 listed active-source file hashes matched current bytes.

Stored report

ERC and DRC

ERC records two excluded warnings and no active errors. DRC records 13 findings: eight solder-mask bridges and five library-footprint mismatches, with zero unconnected items. DRC is not clean.

Limited geometry evidence

Outline and ground zones

The fabrication profile matches 50 × 160 mm and inspected GND Gerber command centers did not extend to the older 50 × 180 mm zone bounds. The stale source-zone definitions remain and full CAM/electrical equivalence was not established.

Open issue

Procurement metadata

PCB and schematic/BOM MPN fields differ for J_RF1, J_SD1, J_USB1, and U2. The J_USB1 PCB MPN field retains USB4105-GF-A-120 while the current schematic/BOM identifies USB4940-00-A.

Not verified

Physical validation

CAM, stackup, impedance, stencil, first-article inspection, and bench validation are not verified by the audited evidence. V4 has not flown.

07 / Reflection

Challenges & Lessons Learned

The observed revision history shows why release review must compare source intent, generated outputs, and procurement data instead of trusting any one file in isolation.

  • Names can lag function. A legacy connector reference can survive after the electrical purpose changes, so current values and nets matter more than the refdes alone.
  • Rendered output can hide stale source geometry. Inspected GND Gerber command centers remained within the 50 × 160 mm profile even though older zone bounds remain in source; this does not establish all rendered copper or aperture extents.
  • Release preparation is not hardware validation. Hashes, BOM/CPL parity, and manufacturing files reduce ambiguity without demonstrating an assembled system.

08 / Outlook

Next Steps & References

  1. Reconcile connector and component procurement metadata across schematic, PCB, and assembly outputs.
  2. Review or correct the historical internal-plane zone bounds, then freshly run ERC/DRC and classify every remaining finding.
  3. Complete manufacturer CAM, stackup, impedance, stencil, and connector-fit review before authorizing production.
  4. Keep fabrication, first-article inspection, bench testing, and flight testing as separate evidence gates.
